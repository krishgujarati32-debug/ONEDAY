# ONEDAY resource-learning sequence upgrade

**Final audit supersedes the initial verification notes:** see the [strict resource-by-resource audit](D:/ONEDAY/docs/resource-final-audit.md) for the 59 authored contextual revisits, final test results and the MeitY content-verification exception.

Implemented locally on November 3, 2026. Production, GitHub and Supabase data were not modified. Review the local result before committing or deploying.

## A. Repository audit

The clean initial repository contained 12 phases, 82 topics, 1291 lessons, 42 resources, 48 technologies and 7 projects. The source of truth was the local files, rather than the live site or an assumed topic numbering scheme.

- Curriculum: `outline.json`, `knowledge.json`, `lessons.json` and `curriculum.ts`; generated client/validation data: `index.json` and `ids.json`.
- Resources: `resources.ts`; technology priorities: `technologies.ts`; persisted checklist order: `projects-outline.json` through `projects.ts`.
- Audited the resource library, topic room, project detail, search endpoint, state/import validation, authentication boundary, SQL migrations and existing tests.
- Original Resource fields were id, title, provider, category, description, URL, type, free and broad phase tags. There was no resource priority or learning-moment schema. Topic/resource relationships lived separately.
- The exact pre-edit IDs, titles, URLs, topic relationships, priorities and project requirements are in [the immutable baseline](resource-upgrade-baseline.json). The full initial 42-resource table, phase/topic inventory and technology classifications are in [the pre-edit audit](resource-upgrade-audit.md). The capture script refuses to overwrite an existing baseline.
- AI Backend Reliability is actually topic 7.6. The recommendation retains that real location. No thirteenth phase or phase rename was introduced.

The final catalog has 51 resources with 130 learning moments, 83 topics, 1313 lessons, 53 technologies and the same 7 projects.

Each resource now has separate resource priority, accurate content type, reading-access status, primary placement, related topic IDs, ordered learning moments, prerequisites and selected previous lessons, focus sections, objectives, exact timing, reason, exercise, completion criteria, next topic/project links and dated link-verification metadata. Phase/topic names resolve from canonical IDs; labels and counts are derived.

One canonical resource ID and bookmark key serves every visit. Resource Library shows one entry per resource. Recommended Learning Order groups matching visits under all 12 actual phases, with one resource card per applicable phase. Phase and timing filters intersect on the same visit. Topic panels and project resource guides read the shared catalog. Search includes prerequisites, reading sections, tasks and topic/phase names. Long guides expand on demand.

An independent resource-study status was intentionally omitted: adding it would change the existing persisted snapshot/RPC contract. Existing resource bookmarks support returning later, and resource reading never changes lesson completion. No database migration is required.

## D. Curriculum changes

The audit found scattered application/security prompting material but no dedicated foundation covering message roles, context design, reusable/versioned templates and prompt regression testing together. Added **6.7 — Prompt Engineering and Context Design**, CORE, immediately after 6.4 and before 6.5. The non-sequential ID preserves every existing ID and the relative order of existing topics. Its 22 new lesson IDs are 6.7.1–6.7.22:

2. System messages.
3. Developer instructions.
4. User messages.
5. Instruction hierarchy.
6. Prompt structure.
7. Clear task definition.
8. Context provision.
9. Few-shot prompting.
10. Zero-shot prompting.
11. Structured output.
12. JSON output and schema validation.
13. Prompt templates.
14. Prompt variables.
15. Prompt versioning.
16. Prompt reuse.
17. Context window management.
18. Context engineering.
19. Prompt injection awareness.
20. Prompt testing.
21. Prompt optimization.
22. Prompt regression testing.
